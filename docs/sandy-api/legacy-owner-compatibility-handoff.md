# Legacy owner compatibility: seven original operation IDs

This candidate adds executable handlers for `github.read`, `github.update_file`, `github.commit`, `github.merge`, `github.push_files`, `supabase.apply_migration` and `supabase.deploy_edge_function`. It is source-tested, closed and unverified. No provider mutation or real Controller session was used; no original161 requirement is newly certified complete by these component tests. Central routing and production deployment are parent-owned follow-up steps.

The private service entry is `sandy-legacy-compatibility-api/index.ts`. `gateway.ts` exports `legacyOwnerOperations`, `legacyOwnerContractMatches` and `legacyOwnerExecutionScope`. Central routing must require a confirmed actual current owner, exact immutable approval, nondelegability, current contract and fixed resource scope. Pass the original operation, arguments, actor/request/admission/grant and null tenant/credential identity unchanged. The service bearer is transport identity. The backend rechecks the real-user admission and immutable approval, consumes once in the shared canonical engine, obtains the bound provider credential only after consumption and finishes once. Do not alias through a second HTTP handler or transfer a canonical operation's approval.

The new optional factory catalogues are deeply frozen trusted source. Their exact original-operation lookup cannot fall back to the default provider catalogue. Default595/provider expansion and default28 supplemental descriptors, scopes and contract hashes are unchanged. The shared business execution remains in the existing provider and supplemental factories. A new fixed native GitHub batch helper is called by the supplemental dispatcher; callers cannot supply an endpoint, callback or GraphQL document.

The GitHub native mutation document is fixed in `_shared/sandy_github_batch.ts`. The vendored schema excerpt and source JSON pin the reviewed public Octokit schema bytes, including native `expectedHeadOid`. A stale preflight head refuses before mutation; the provider's native compare-and-swap protects the preflight-to-write interval. Successful readback is an observation, not a claim that a later external writer cannot move the branch. Invalid/lost mutation receipts or missing/mismatched readback require reconciliation and never trigger an automatic second write. Neither supplied file bytes nor source text are included in the public batch receipt.

`artifact_ref` hashes the canonical manifest containing fixed project, slug/name, entrypoint, optional import-map path, verify_jwt=true and sorted path/content-digest records. The existing deploy executor's `source_sha256` has its existing file-set encoding. Deployment metadata readback checks ID/version/JWT metadata; it is not deployed-source-body attestation. No real deployment effect is claimed by local multipart tests.
