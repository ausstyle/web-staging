## One-use admission and evidence

Service-only database admission independently checks the actual running examiner run/cutoff, channel cursor, inbound source, exact fixed source guard and source/customer snapshot. It saves the server-read bounded context and creates a one-use **channel/source** receipt before any model request. Free-text source fields are uploaded as bounded per-field UTF8 SHA256 witnesses; IDs, tenant/session scope and timestamp fields are checked exactly (timestamp instants normalize their textual representation). Null stays JSON null, while empty text has its non-null SHA256. SQL computes matching UTF8 digests from the actual row and retains the full actual source snapshot locally. This avoids introducing a 32KB raw-source rejection for legitimate future long messages while preserving detection of edits anywhere in the source. The bounded context envelope permits its worst-case escaped Unicode/control text without discarding its existing semantic budgets. A new run ID cannot repeat an unresolved source. Rows already present in the actual review table are returned without another model call, so a lost cursor save does not consume model resources twice.

Context is an observed server-read snapshot. The primary source is rechecked and locked during finalization; changed source/customer facts refuse stale completion. Paired replies and previous messages are captured observations, not a promise that those other rows never change after the read. The audit stores the actual admitted context and hash. The channel's receipt label identifies the pairing rule; it is not independent proof of delivery or successful external action.

The output field `model_request_attempted` reports an attempted request, **not billing or successful model execution**. A reused historical record lacking an audit receipt reports null when the attempt is unknown. A valid stored evaluated legacy verdict implies that the old implementation attempted its model request; its pass still does not prove external action. Legacy stored `not_run` rows do not establish whether a model request was attempted; the historical attempt remains null without a receipt. For new planned requests, the fallback is set to judge_unavailable **before** dispatch and only a valid evaluated response replaces it. Empty output, malformed JSON, missing/unsupported verdicts and incomplete/failed envelopes remain unavailable. SQL rejects planned requests labelled not_run. An absent API key or reply retains not_run without inventing a successful review. Evaluated quality scores must be JSON numbers that are integers 1..5, or JSON null; a numeric 2.0 normalizes to 2 while a string "5" is refused. A lost optional model response records judge_unavailable and the original needs_review/unverifiable fallback, with no automatic paid redispatch.

Finalization atomically stores the actual review and, only for potential_issue, its existing investigation intake, explicitly inserted as discovered/unassessed/approval_required true rather than relying on mutable defaults. The original finding-capture trigger remains enabled. Intake stays unassessed, unverified and undeployed. A missing final receipt or changed primary source leaves a durable unknown source result; future runs cannot send another model request. A response lost after an actual committed review can be reconciled by reusing that real saved row.
