# Typed financial export

This source adds three owner-approved artifact operations and two actual-customer delivery operations for a fixed ten-table financial manifest. The new operations remain closed and unverified. It captures installed commerce configuration, consent records, accounts, entries and lines, statements and lines, reconciliation records, invoices and entitlements. It does not erase or restore financial source data, perform payments, attest provider settlement, replay permissions or claim complete tenant coverage. Global plans/prices/contracts and admission-linked financial/control results, effects and product mutation-evidence copies remain excluded pending their dedicated retention/redaction adapters.

Every integer amount, numeric(30,0) total and invoice counter is encoded as a decimal string. NaN/infinite numerics and infinite timestamps are refused. Invoice item and reconciliation-match JSON accept only their exact supported keys/types; arbitrary future JSON fields cannot enter an export. Matches are historical internal records with provider_verified=false. Entry-line ownership follows its entry; statement-line ownership follows its statement. The capture checks linked accounts, reversal entries, reconciliation statements/candidate entries/statement lines and source email messages belong to the same customer. Foreign malformed JSON is outside the selected tenant and cannot break its export.

Migration 07280 extracts the original typed content capture into one private fixed-manifest engine, retaining the old content wrapper and adding the financial wrapper. Migration 07290 extends the same encrypted fragment journal, metadata, immutable receipts, owner proof, one-use grant, audit and governed artifact purge. The journal gains an explicit manifest ID; old and new discovery/download paths select only their fixed manifest. Customer delivery derives the confirmed portal tenant from the actual JWT and cannot accept a customer or actor ID. Private scoped helper functions remain revoked from public, anonymous, authenticated and service roles; fixed wrappers supply their reviewed operation/manifest pair. Existing customer-content exports retain their old public schemas and hashes.

Fragments preserve canonical NDJSON across Unicode boundaries, exact decoded UTF-8 SHA-256, per-table row digest chains and a safe custody index. Bounds remain 65,536 Unicode characters per fragment, 16 MiB per row, 128 MiB per artifact, 2,048 fragments and 50,000 rows per table; overflow aborts instead of truncating. The default delivery deadline is 24 hours. Explicit artifact purge requires current erasure consent and respects holds/retention; it removes encrypted custody while preserving posted history, numbering and all original financial source rows. No automatic purge or financial retention period is invented.

Migration 07295 adds three explicit choices to the existing customer consent wire contract, for 68 reviewed choices within the existing capacity of 128. There is no automatic grant, expiry extension or permission restoration. Both customer consent and delivery use normal user-bound database clients. Administrative credentials never stand in for a customer session.

Six Deno checks, 19 native database checks and 20 governed fragment database checks pass. A combined actual PostgreSQL full-rollback run passes 175 checks across the existing service, tenant leaves, scalar links, typed customer content, support recovery, new financial capture/delivery and 68-choice consent. It includes a 3.4 MiB Unicode source, exact values beyond JavaScript integer precision, numeric(30,0) invoices, foreign ownership/JSON refusal, native posted-history protection, customer isolation, digest/reassembly, current-consent/hold/retention gates and compatibility with existing content delivery. Cleanup confirms no new financial functions/contracts or synthetic Auth rows remain. These administrative fixtures are not genuine Controller/customer-session transport or provider attestation.
