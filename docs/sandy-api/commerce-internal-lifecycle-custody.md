# 53 commerce operations lifecycle custody

This inventories all 15 new 09100 tables. They have RLS enabled and no direct PUBLIC/anon/authenticated/service_role table grants. Authenticated typed RPCs are the only normal writers. There are no automatic pollers, cron jobs, network triggers or provider credentials. Three local guard triggers reject edits/deletes of posted entries/lines and financial edits of issued/void invoices. Customer FKs use RESTRICT. No legal/accounting retention period is invented; financial state requires a dedicated approved lifecycle policy. Do not add these tables to automatic generic export/erase/restore based solely on a customer UUID.

| Table | Ownership and exact projection candidate | Retention and reference constraints |
|---|---|---|
| sandy_commerce_configuration | customer_id→email_customers; currency,minor_unit_exponent,invoice_prefix,next_invoice_number,default_terms_days,version,created_at,updated_at | Preserve numbering and currency/unit history. Generated next_invoice_number controls future issuance; restoring an old counter risks duplicates. Never restore as a payment-provider configuration. |
| sandy_commerce_consents | customer_id→email_customers; terms_version,invoice_forwarding_allowed,automatic_renewal_recorded,expires_at,revoked_at,revision,updated_at | Commercial permission record, not lifecycle consent or verified legal terms. Preserve latest revocation; never restore an old opt-in/renewal record. It cannot authorize a processor charge. |
| sandy_commerce_accounts | customer_id→email_customers; id,code,name,kind,currency,minor_unit_exponent,active,version,created_at,updated_at | Retained financial account identity. Entry lines and statements reference accounts with RESTRICT; account closure does not erase history. |
| sandy_commerce_entries | customer_id→email_customers; id,description,external_reference,effective_at,state,currency,minor_unit_exponent,version,reversal_of,posted_at,created_at,updated_at | Posted entries are immutable. reversal_of uniquely references another entry with RESTRICT. Do not erase or restore a posted/reversal chain without explicit financial policy. |
| sandy_commerce_entry_lines | entry_id→owned entries; id,entry_id,account_id,debit_minor,credit_minor,description | entry_id CASCADE only for a deletable draft; account_id RESTRICT. Posted-parent and posted-line guards prohibit mutation. Export money as decimal strings. A customer UUID on another joined row cannot replace the entry ownership path. |
| sandy_commerce_statements | customer_id→email_customers; id,account_id,source_reference,source_kind,content_sha256,created_at | Explicit manual_unverified source. Account FK RESTRICT; reconciliations retain statements with RESTRICT. No bank connector or credential is stored. |
| sandy_commerce_statement_lines | statement_id→owned statements; id,statement_id,external_reference,effective_at,amount_minor,description | Statement CASCADE only when unreconciled manual statement deletion is allowed. Amount is signed decimal string. |
| sandy_commerce_reconciliations | customer_id→email_customers; id,statement_id,state,matches,version,reviewed_at,created_at | Retain financial review evidence. matches JSON contains statement-line IDs, candidate entry IDs, external references and decimal amounts; no credential. Parent statement FK RESTRICT. Restoring a proposed snapshot is not confirmation or a provider payment. |
| sandy_commerce_invoices | customer_id→email_customers; id,counterparty_name,external_reference,currency,minor_unit_exponent,items,subtotal_minor,tax_minor,discount_minor,total_minor,due_at,state,invoice_number,version,source_message_id,forwarding_status,payment_status,created_at,updated_at | items JSON contains user text, quantity and decimal money. source_message_id→email_messages RESTRICT is an incoming lifecycle deletion dependency. Issued/void financial fields are immutable. Counterparty text can contain PII. Payment status always unverified. Restoring must not issue, forward, pay or reopen numbering. |
| sandy_commerce_plans | Global actual-owner catalogue; no customer projection | Preserve global commercial configuration and version/archive state. prices.plan_id RESTRICT. Not a customer purchase. |
| sandy_commerce_prices | Global plan_id→plans; no ordinary tenant projection | Preserve immutable currency/unit/amount/interval history and archive state; no provider price or secret exists. |
| sandy_commerce_entitlements | customer_id→email_customers; id,feature_key,expires_at,revoked_at,reason,version,updated_at | Actual owner grant, not paid entitlement. Preserve latest revocation/expiry; do not restore grants or invent authorization from a snapshot. reason may contain PII. |
| sandy_commerce_contracts | Global immutable catalogue; no customer projection | Preserve control schemas/hashes; no tenant ownership. |
| sandy_commerce_results | admission_id→shared admissions; no generic safe projection | Retain control receipts. result JSON can include journal/invoice descriptions, counterparty PII, manual statement text and amounts, scoped configuration/consent/entitlements, and failure outcomes. Financial content also appears in shared sandy_product_mutation_evidence before_state/after_state. No credentials/card data are accepted. |
| sandy_commerce_effects | admission_id→shared admissions; nullable customer_id→email_customers; operation,actor_kind,created_at are provenance | Preserve audit provenance with RESTRICT references. Owner global writes have NULL customer; owner entitlement writes record target customer while preserving the real owner Auth actor in admissions. Never infer customer impersonation from the target UUID. |

Incoming and outgoing deletion constraints are explicit: lines→entries CASCADE and accounts RESTRICT; statement lines→statements CASCADE; statements→accounts RESTRICT; reconciliations→statements RESTRICT; invoices→email_messages RESTRICT; entries.reversal_of→entries RESTRICT; prices→plans RESTRICT; results/effects→shared admissions; all direct customer references RESTRICT. No generated identity besides UUID defaults/created timestamps is safe to treat as portable authorization. Invoice next-number, versions, posted/reversal state and idempotency/audit identities have functional meaning.

Account export can eventually include approved financial content with decimal precision and lineage preserved. Erasure, restoration, retention/redaction of audit copies, legal holds and external message cleanup require dedicated policy/adapters. Scope 111 must report these as financial/control/consent/entitlement exclusions and partial coverage until reviewed. No secret reference, Auth account, customer key, owner role, recurring charge or provider authorization is restored from this data.
