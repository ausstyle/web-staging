# Mission committed-draft acknowledgement recovery

A same-request subset of SANDY-ENG-0004 MTR-T01 (not process-restart recovery): a draft can commit atomically, then lose its final HTTP acknowledgement. The deployed executor23 reported unknown despite the canonical terminal receipt and correctly refused duplicate model execution. The bounded repair reads that existing receipt once, requiring exact audit/run/customer/mission/source identity, terminal state, original provider response and payload digest, original normalized draft digest and valid product/review IDs. A waiting receipt must have the exact waiting reason and no provider or product evidence. Missing, malformed, foreign, nonterminal or mismatched evidence remains unresolved. No model or successful-finalization retry is added. An unresolved outcome makes one best-effort unknown-marking call to the existing RPC; if that transport also fails, return bounded uncertainty. Terminal SQL receipts cannot be overwritten.

Read-only source inspection matched the deployed worker to the repository preimage. Existing service_role can SELECT the receipt table and cannot UPDATE it directly. No schema, grant, identity or public operation changes are required. The existing finalization RPC and immutable trigger retain authority for publishing drafts/reviews. No future executing authority is inferred from the recovered historical receipt, and mission completion/external execution remains false.

Validation: ten existing executor tests and two PGlite persistence test groups covering twelve fault scenarios pass: committed lost/thrown acknowledgement, waiting without a model request, rollback, read error, thrown read plus thrown unknown-marking transport, foreign customer, changed source/provider/draft digest, unknown state and absent review. SQL writes are real isolated transactions; provider and RPC transports are fixtures. These tests prove worker recovery and duplicate suppression, not production RPC concurrency or actual provider failure injection.

Protected selection mission-reconciliation installs only sandy-mission-executor, using its captured six-module version23 preimage and replacing only worker_mission.ts. It verifies all installed modules and stores compatible rollback material. It does not invoke the timer, dispatch a mission, repeat accepted effects, or change Runtime41. Deployment/source verification is separate from live lost-acknowledgement acceptance, which remains unclaimed.

If the receipt read is unavailable, do not redispatch the model. Preserve the original unknown/terminal evidence and use supported read-only reconciliation. Broader crashed-worker watchdogs, leases, DAG recovery and multi-step mission acceptance remain outside this patch.
