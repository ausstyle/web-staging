API & Integrations

Connect your applications to Sandy's tasks, calendar and file catalogue. The API uses JSON POST requests and scoped bearer tokens.

Integration rollout: The API is in controlled rollout. Key management requires a signed-in Sandy client session. Do not place secret API keys in browser-side code.

Endpoint

POST https://zmqlyygzqoidkcwdysok.supabase.co/functions/v1/sandy-operations-api

Authentication

Use Authorization: Bearer sandyop_... from your server. Generate keys using keys.create with your authenticated client login token. The secret is returned once only. Revoke compromised keys immediately with keys.revoke.

Operations

AreaAvailable calls
Discoverysystem.catalog
Keyskeys.list, keys.create, keys.revoke
Taskstasks.list, tasks.get, tasks.create, tasks.update, tasks.complete, tasks.archive
Calendarcalendar.list, calendar.get, calendar.conflicts, calendar.create, calendar.update, calendar.cancel
Filesfiles.list, files.get, files.search, files.rename, files.set_description, files.archive

Scopes

tasks:read tasks:write calendar:read calendar:write files:read files:write

Example

curl -X POST 'https://zmqlyygzqoidkcwdysok.supabase.co/functions/v1/sandy-operations-api' \
  -H 'Authorization: Bearer YOUR_SECRET_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"operation":"tasks.list","arguments":{}}'

Important limits

File rename and archive operate on Sandy's canonical metadata, not the underlying Google Drive or other provider file. A success response is not proof that external file bytes were changed. External write calls require an idempotency key; avoid retrying ambiguous writes until operation receipts are available. The current API is not a complete representation of all workspace features.
